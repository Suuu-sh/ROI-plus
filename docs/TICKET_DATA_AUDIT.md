公式オッズページはHTML内の選択中レースタブで日付・場・Rを示し、「締切時オッズ」と3連単表を含む。新しい `parseTrifectaOdds` はこのページ内のレース識別子、締切/更新時刻表示、表構造を照合し、3連単の順序付き selection 全120件が重複なく正数値である場合だけ通す。確認ページでは120件・ユニーク120件で、ページ識別子は期待値 `2026-10-04 / 09 / 3R` と一致した。欠場等の表記、欠落・追加・重複セル、変更されたマークアップは現バージョンでは失敗扱いとし、欠損オッズの補完や「120件扱い」はしない。

公式結果ページの上位着順と3連単払戻を照合した結果:

- 着順: `4 → 2 → 1`
- 公式払戻: `4-2-1`, 19,570円 / 100円
- 同じ組番の締切時オッズ: `195.7`
- 数値照合: `195.7 × 100 = 19,570`、完全一致。選択順序も一致し、不一致0件。

ローカル `ml/data/rows.json` の同一 race ID（`boat-20261004-09-03`）も限定確認した。正規化済み結果6艇の上位3着は `4-2-1` で公式と一致し、3連単払戻に `4-2-1 / 19,570円` があり公式値とも一致した。一方、同じ race ID にもう1件 `1-4-2 / 710円` の3連単払戻が存在した。公式結果の的中3連単は1件のみなので、この追加行は不整合として数えられる（確認したローカル結果6件、3連単払戻2件、期待選択と一致1件、余分な払戻1件）。このため、本例の「的中選択・払戻値」単体は一致するが、正規化済み払戻集合全体の整合性は不一致であり、Kパーサー／入力元の調査と誤行の隔離が必要。これを修正・再正規化したとは扱わない。全履歴の監査はしていない。

公式サイトの「締切時オッズ」は発売票数集計完了時の表示であるため、購入判断時点の価格と同一視できない。返還・発売停止等があるレースや別タイミングの表示では払戻と単純一致しない可能性があり、実装では購入時スナップショットと締切時値を区別する必要がある。

## 実装境界

- `apps/api/src/services/boatraceTrifectaOdds.ts` は公式 `odds3t` URL生成、ページ識別子のfail-closed検査、3連単120組のパース、および公式結果ページの上位着順・3連単払戻の監査用パースを提供する。
- 品質値は最終オッズなら `verified-final-complete-v1`、締切前の完全な非最終ページなら `verified-complete-v1`。どちらもパーサーの形式・完全性検査に合格したことを表すだけで、利用許諾、価格の市場品質、損益上の妥当性を保証しない。最終値は監査表示用で、締切前候補や購入判断に使わない。
- 取得側は同一HTTP応答の正確なSHA-256、公式URL、実際の取得時刻 `captured_at`、source識別子を保存する。過去日付の公式ページを今取得した場合、`captured_at` は取得時刻であり、過去の購入時点を再現する証拠ではない。
- 公開ページを低頻度で読めることは自動取得の利用許諾を示さない。本監査は許諾を確認しておらず、本番Worker収集・デプロイ・リモートDB変更は行っていない。収集フラグの設定値も稼働環境の証拠ではない。
