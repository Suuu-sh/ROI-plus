# 三連単のカバレッジ・候補適格性

`train-trifecta` の前後に、保存済みローカルストアをネットワークなしで監査できます。

```sh
PYTHONPATH=ml python3 -m edgelab.models.trifecta_coverage \
  --store ml/data/rows.json --details
```

レポートは全完了済み実ボートレースを分母にし、艇・着順、確認済み締切、締切時刻の観測、出走データの到着時刻とSHA-256、T-60までの展示・気象、締切前120組オッズ、K着順と一致する三連単払戻を別々に数えます。欠落・古い・時点後の観測は除外理由に残し、後日の値で補完しません。`--output` を使う場合は新規ファイル名だけを指定します。対象実データがない場合や証拠が不足する場合は終了コード2です。

## 点時点とデータ出所

- 学習対象は `data_origin=real` のみで、1レース6艇と順位1〜6が完全に一致する必要があります。
- V2の予測境界は、公式の確認済み締切の60秒前です。締切日付は日本時間の開催日と一致し、締切は発走時刻以前、締切自体の取得時刻もT-60以前でなければなりません。予測境界後に取得した情報は使いません。
- 出走表の `available_at` だけでは原本の到着時刻を証明しません。各艇にT-60以前の `source_available_at` または `source_observed_at` と、それに結び付くSHA-256が必要です。現在のBファイル日時は開催日午前0時の仮定であり、実測の公開・取得時刻ではありません。
- 展示・気象の特徴量は、明示的なfixtureでなく、実データである同一レースの公式 `beforeinfo` URL、SHA-256、タイムゾーン付き取得時刻が一致し、T-60までに取得された30分以内の観測だけから選びます。原本の観測時刻が取得時刻より後なら除外します。入力順に依存せず、最も新しい適格観測を選びます。表示ラベルだけで正確な気象観測時刻が分からない行は除外します。
- 三連単リプレイには、T-60時点で有効な、公式・非確定・同一本文SHAの完全な120組市場と、着順に一致する唯一の正の実払戻が必要です。後から取得した市場、部分市場、サンプル行はROIに含めません。

## 候補の評価と昇格

三連単確率は合法な順序付き組番120件をすべて出し、有限値・0〜1・合計1を検証します。holdoutの完全着順を1レース単位で採点し、exact-order Log Loss、120クラスMulticlass Brier、トップ券ECE、bin別レース数を報告します。全120券を平坦化したpooled ECEは参考値です。

候補適格性の固定条件は次のとおりです。条件を後から成績に合わせて緩めません。

- 学習300レース以上、時間順holdout400レース以上・7日以上。
- トップ券ECE 0.05以下。
- train期間だけで作った艇番順序基準に対し、Log LossとBrierのrace bootstrapおよびdate-cluster bootstrapの95%上限がすべて0未満。
- 同一T-60意思決定の実オッズ・一致する実払戻を使ったリプレイが30レース以上あり、race/date両bootstrapのROI 95%下限が0より大きい。
- 完了済み実レース全体で、締切・到着時刻・特徴観測・120組オッズ・払戻のpoint-in-time証拠がそろう。

ローカル学習はモデル行を `candidate` のまま保存し、`promotionEligible=false` を維持します。offline評価が通っても自動昇格せず、APIが要求する新しいartifact SHAに結び付いた独立チケット検証証跡が別途必要です。稼働後のrollbackも人手操作で、退役先モデルの独立検証証跡が現行ゲートを通る場合だけ可能です。確率品質やcounterfactual replayは、将来の利益や実購入成績を証明しません。
