## 実装意味の確認

- `/api/bets/experimental` は固定実験の「placed ticket」だけを最大500件返し、棄権判断や全予測候補は返さない。応答には購入時 `predictedProb`、`oddsAtBet`、精算 status、`officialSelection` が含まれる（`apps/api/src/index.ts` の `/bets/experimental` route）。
- 保存時の予測スキーマは `exact-selection-probability-v1`、かつ正規化された全120個の順序付き三連単分布を要求する（`apps/api/src/index.ts` の forecast validation）。これは「その順序の3連単が的中する確率」で、1着確率などの意味ではない。
- 購入APIはベット済み券の部分集合。よって仮にその部分集合の校正を測れても、モデルの全分布校正ではなく、選択ルールで条件づけられた結果となる。複数券/レースは排他的で相互依存し、独立なチケット試行として通常の信頼区間を出すのは不適切。
- `/api/performance/experimental` は成績・賭け金比較を返すが、信頼できる全予測分布・予測ごとの実結果ラベルを返すものではない。
- 監査JSONは `docs/reports/experimental-trifecta-calibration-2026-10-17.json`。購入元・性能比較レスポンスの SHA-256 と観測時刻、集計値とモデル別集計だけを保存し、券単位の生レスポンスは含めない。

## 再利用可能な監査

`ml/edgelab/calibration/experimental.py` は `/api/bets/experimental` のJSON配列を入力にするオフライン監査器。real の settled won/lost のうち、公式上位3着と券の一致、確率・オッズの妥当性が整合する記録だけを採用し、open、void/reconciled、非real、その他状態、重複ID、不整合を件数付きで除外する。予測確率デシルと購入オッズ帯の予測平均/実的中率、平均オッズ/損益分岐確率、期待・実的中数、Brier、log loss を出し、区間はレース単位 bootstrap で計算する。オッズの逆数は市場マージンを含む比較値であり正解確率とは扱わない。

認証済み環境からエクスポートした配列を使う場合:

```sh
PYTHONPATH=ml python -m edgelab.calibration.experimental bets-experimental.json \
  --performance-input performance-experimental.json \
  --observed-at 2026-10-17T10:14:15+09:00
```

## 原因について

**確認済みの原因:** モデルが全予測分布で長穴を過大評価する原因は特定できていない。個別因果の主張に必要な全120選択予測と非選択券もない。一方、保存済み購入確率と実結果の差そのものは、上記選択券コホートで確認した。

**未検証の仮説:** 学習標本の薄さ、時間/場の分布ずれ、確率尾部の校正不足、候補選択による選択バイアス等は調査候補だが、今回の観測では根本原因とまでは判別できない。改善は隔離候補でのみ評価し、全120通りのpoint-in-time予測と未使用の時間分離holdoutを使う。本番推論・購入ロジック・稼働状態の変更、デプロイ、昇格は行っていない。
